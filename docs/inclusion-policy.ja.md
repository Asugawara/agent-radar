# 掲載基準

agent-radar に載せるのは、次の基準をすべて満たすツールだけです。満たさない提案は、外れた基準を書いて閉じます。[提案フォーム](https://github.com/Asugawara/agent-radar/issues/new?template=suggest-tool.yml)では、各基準の判断に必要なことを尋ねます。

English: [inclusion-policy.md](inclusion-policy.md)

## 必須

1. **対象範囲。** AI エージェントを作る・動かす・拡張する・運用するためのツールであること。特定のアプリをエージェントから操作させるツール（例: Blender の MCP サーバ）は対象に入ります。特定の業界向けのサービスやデータ（例: データセンターの立地選定）は対象外です。
2. **いま使える。** 公式サイトかリポジトリが公開されていて、開けること。waitlist だけ、デモだけのものは対象外です。リポジトリがある場合は、archived ではなく、12 か月以内に更新があること。
3. **AI ベンダーの規約に従う。** AI ベンダーが禁じている方法で、サブスクを使わないこと。Anthropic（[規約](https://code.claude.com/docs/en/legal-and-compliance)）と Gemini CLI の Google（[規約](https://geminicli.com/docs/resources/tos-privacy/)）は、第三者のツールが次のことをするのを禁じています。この基準は、ツールの公式プラグインにも当てはめます。
   - Claude や Gemini CLI のサブスクへのログインを、独自に提供する。
   - サブスクのトークンを集める、保存する、中継する。
   - 公式 CLI を装う。借りた OAuth client ID や、偽の User-Agent・system prompt・TLS 指紋を使う。

   次は問題ありません。改変していない公式の CLI・SDK（`claude`、`codex`、`gemini`）を本人のログインで起動すること、API キーで使うこと、ベンダー公式の第三者向けプログラム（例: Sign in with ChatGPT）を使うこと。こうした禁止を公開していないベンダー（2026 年 11 月時点では OpenAI）は、公開されるまで対象にしません。
4. **安全にインストールできる。** ビルド以外のことをするインストール時スクリプトがないこと。難読化されたコードがないこと。ツールの目的を超えて、認証情報やデータを集めないこと。文書に書かれたテレメトリは問題ありません。
5. **まだ載っていない。** agent-radar に載っているツールと同じ製品ではないこと。先にサイトで検索してください。

## 新しく追加するときの目安

6. **使われている。** 次のどれか 1 つを満たすこと。GitHub のスターが 100 以上、パッケージの週間ダウンロード数が 1,000 以上、AI ベンダー自身の公式リポジトリ。すでに載っているツールは、これを下回っても外しません。

## そのほか

- 自分のツールも提案できます。フォームでそう答えてください。ほかの提案と同じ基準で判断します。
- ライセンスは問いません。オープンソース（`open_source = true`）として載せるのは、OSI 承認のライセンスのときだけです。
- 有料のツールも、いま申し込めるなら載せます。
- 基準 1〜5 は、すでに載っているツールにも当てはめます。外れていると分かったツールは外します。
